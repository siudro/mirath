# مِيراث — كيف يعمل الوكيل

هذا الملف يوثّق المسار الفعلي لكل رد، خطوة بخطوة. كل خطوة لها ملف، وكل ملف
قابل للفحص. لا شيء هنا يعتمد على «ثقة» في النموذج.

---

## المسار الكامل

```
   المستخدم: صورة + نص
          │
          ▼
 ┌────────────────────────────────────────────────────────┐
 │  POST /api/chat   (Server-Sent Events)                 │
 └────────────────────────────────────────────────────────┘
          │
          ①  ── فرز الخطورة   [server/server.js · triage()]
          │     قاعدة صريحة، لا نموذج. أي مطابقة في
          │     DANGER_PATTERNS ⇒ تُعلَّم الحالة كطارئة.
          │
          ②  ── قراءة الصورة   [النموذج]
          │     يصف ما يراه فقط. يُلزمه النص بقول:
          │     «الصورة لا تحدد العمق ولا الخطورة».
          │
          ③  ── استرجاع الأدلة   [data/knowledge-base.js]
          │     المواد المرشحة تُحقن في السياق حرفيًا،
          │     مع حكمها ومصدرها. النموذج لا يجتهد.
          │
          ④  ── بحث علمي   [Europe PMC — دون مفتاح]
          │     DOI/PMID حديث يعود إلى السياق.
          │
          ⑤  ── الكاتب   [luna-gpt6 — رؤية]
          │     يكتب المسودة الأولى.
          │
          ⑥  ── المدقق   [نموذج مستقل]
          │     يعارض لا يوافق. يعيد JSON:
          │     { agrees, issues[], corrections }
          │
          ⑦  ── بوابة قائمة التحقق   [config/checklist.js]
          │     ★ ٩ بوابات. واحدها «حرجة» (الخطورة).
          │     إن فشلت الحرجة ⇒ لا تسليم. تصحيح مرة،
          │     وإن بقي فشل ⇒ ردّ إسعافي آمن مُستبدل.
          │
          ⑧  ── صورة المادة   [Wikimedia Commons]
          │     مع الترخيص والمصدر. لا صور للمواد الممنوعة.
          │
          ▼
      الرد النهائي
```

## أدوار النماذج

| الدور | ما يفعله | ما لا يفعله |
|---|---|---|
| **كاتب** | يكتب المسودة من السياق المحقون | لا يقرر ما هو آمن — هذا للبوابة |
| **مدقّق** | يقرأ المسودة بنيّة إيجاد خطأ | لا يعيد صياغة الرد بنفسه |
| **بوابة** | تقرر إن كان الرد قابلًا للتسليم | ليست نصيحة — قانون |

**لا نموذج يقرر وحده.** كلاهما يُنتج، والبوابة تفصل.
وهذا يطابق ما طلبته الطالبة: «وكيل يبحث، وآخر يتحقق، والاثنان يتفقان قبل الرد».

## البوابات التسع

| # | البوابة | ترفض متى |
|---|---|---|
| ١ | الخطورة أولًا ★ | طارئ بلا «طبيب/إسعاف» في أول ٢٠٠ حرف، أو عشب |
| ٢ | سؤال واحد فقط | أكثر من علامة استفهام |
| ٣ | لا يبدأ بسؤال | أول جملة استفهام |
| ٤ | كل مادة بحكمها | ذكر مادة بلا ✅/⚠️/❌ قريب منها |
| ٥ | الصورة لا تكفي | صورة بلا تنبيه على العمق |
| ٦ | النطاق | سؤال خارج الجروح بلا توجيه |
| ٧ | لا دواء ولا جرعة | اسم دواء أو رقم جرعة |
| ٨ | لا مرجع مُختلق | PMID خارج القاعدة، رقم صفحة على ابن سينا |
| ٩ | الطول | أكثر من ١٢ سطرًا |

★ = حرجة. فشلها يمنع التسليم بلا استثناء.

## ما رُفض فعليًا (سجل تجريبي)

| الحالة | ما حدث | النتيجة |
|---|---|---|
| رد طارئ بدأ بـ «اضغط بقماش» بلا توجيه طبي | البوابة الحرجة رسبت | **استُبدل بردّ آمن** |
| «العسل» مذكور بلا حكم | البوابة ٤ رسبت | أُعيد التصحيح |
| «العسل — كانوا يستخدمونه قديمًا» (بلا حكم) | البوابة ٤ رسبت | أُعيد التصحيح |
| «لا تضع أي مادة أو عشب» في الطوارئ | نُهي عن العشب — ليس اقتراحًا | **مرّ بشكل صحيح** |
| «استخدم زيت الكافور» في الطوارئ | مادة ممنوعة في طارئ | **رسب** |

انظر `tests/checklist.test.js` — كل صف من هؤلاء اختبار مثبّت.

## الواجهة

- **لوحة الأثر:** كل أداة تعلن نفسها (`tool: start`) ثم نتيجتها (`tool: end`).
  المستخدم يرى «أتحقق من الخطورة» ثم «لا إشارات خطورة» — لا شاشة صامتة.
- **الحركة:** نبض ورقة، انجراف ضوء، خط الحياة في لوحة الأثر. كلها بطيئة،
  وتحترم `prefers-reduced-motion`.
- **السجل:** يُخزَّن في `localStorage` (٥٠ محادثة كحد أقصى)، مع حذف يتطلب تأكيدًا.
- **علامات الحكم:** رموز نصية (✔ ✘ !) في شارات دائرية — لا إيموجي، لأنه يُرسم
  مربعًا فارغًا على أجهزة كثيرة، والعلامة هي الحكم نفسه.
